# v2 plan: room types, rock and obstacles as input, mountain bases

Written 2026-10-28, after the v1 baseline on more data (docs/HISTORY.md). Status: room types and defences decided 2026-10-29; step 1 (data) done 2026-10-29, `data/sets/v2_48`.

## Why

- v1 draws walls without a purpose: a layout is only wall/door/floor, so nothing ties a room's size and shape to a use.
- Mountains and other obstacles can only be shown to v1 as fixed tokens (empty, wall, shell). It never saw fixed regions in training,
  so near them it draws solid wall masses (in game, 2026-10-28).
- 2.4x more data improved v1 only moderately (rooms with a door 77% → 86%). The remaining faults come from how the model is set
  up, not from the amount of data.

## Changes

### 1. Room types as categories

Each cell inside an enclosed, roofed room gets the room's type instead of plain `floor`. The type comes from the things inside the
room, as the game does with room roles. Rules are kept in the config as regex lists, like the category rules.

- **Decided 2026-10-29 (user):** 18 room types. Counts below are from all 8,508 snapshots (116,029 roofed rooms of 4–600 cells),
  with the final rules:

  | Type | Rooms | Share | Median size (10th–90th percentile) |
  |---|---|---|---|
  | `bedroom` (1–2 beds, deathrest caskets) | 41,418 | 35.7% | 20 (9–42) |
  | `room_untyped` (contents match no type, or only one small table) | 15,460 | 13.3% | 35 |
  | `room_empty` (nothing inside) | 9,240 | 8.0% | 20 (6–72) |
  | `storage` (shelves and racks, or 3+ item stacks) | 8,867 | 7.6% | 62 |
  | `barracks` (3+ beds) | 5,478 | 4.7% | 48 (20–140) |
  | `kitchen` (stove, butcher table, brewing) | 4,331 | 3.7% | 30 (9–105) |
  | `utility` (power, plus Dubs Bad Hygiene plumbing: boilers, tanks, pumps, treatment) | 4,141 | 3.6% | 45 |
  | `workshop` (crafting benches, smithy, drug lab) | 4,046 | 3.5% | 76 (21–214) |
  | `bathroom` (toilet, bath, shower) | 3,878 | 3.3% | 15 (6–102) |
  | `dining` | 3,108 | 2.7% | 113 (40–242) |
  | `hospital` (hospital or operating beds) | 2,775 | 2.4% | 48 |
  | `rec` (games, TV, instruments) | 2,413 | 2.1% | 76 (30–200) |
  | `lab` (research benches, gene lab) | 2,184 | 1.9% | 63 (24–171) |
  | `barn` (animal beds, troughs) | 1,865 | 1.6% | 56 |
  | `freezer` (storage with a cooler in its wall) | 1,443 | 1.2% | 60 |
  | `temple` (altar, ideogram, lectern, throne) | 1,350 | 1.2% | 90 |
  | `crypt` (graves, sarcophagi) | 1,206 | 1.0% | 132 |
  | `nursery` (cribs) | 737 | 0.6% | 25 |

- Type rules:
  - **Beds decide first:** hospital beds give `hospital`, cribs give `nursery`, deathrest gives `bedroom`, 1–2 beds give `bedroom`,
    3+ beds give `barracks`. Animal beds don't count as beds.
  - **Dining:** only with 2+ tables, or one table of 2x4 or larger (8+ cells); it then wins over other furniture. A single small
    table counts for nothing, so the room takes the type of its other furniture. Chairs never count.
  - **Otherwise** the type with the most matching things wins. Typical mixes are storage+workshop (2,661 rooms),
    lab+storage (950) and kitchen+storage (838).
  - **Rare kinds:** brewery goes to kitchen, gene lab to lab, throne room to temple. Biosculpter, command, armory, greenhouse,
    classroom, library, gym and Anomaly containment are each under 0.5% and stay `room_untyped`.
- Rules for later: some things in untyped rooms could still be matched (`Bin_*` as storage, `ElectricSmelter` as workshop,
  `Transformer`/`PowerSwitch` as utility, `LWM_Meat_Hook` as freezer).
- Categories outside rooms: `empty`, `floor` (outdoor paving), `wall`, `door`, `fence`, `wall_mounted` (kept).
- **Defences (decided 2026-10-29):**
  - `embrasure`: split out of `wall`; still a wall for rooms and repair.
  - `cover`: sandbags, barricades, barriers.
  - `trap`: spike traps, IEDs, bear traps, caltrops, barbed and razor wire.
  - `turret`: all turrets and mortars, marked at their centre cell.

  Cover, traps and turrets are things, not edifices, so they come from `thing_patterns` in the config.
- In total: **28 categories** (`configs/v2.json`).
- Cells outside rooms keep the v1 categories: `floor` (outdoor paving), `empty`, plus `wall`, `door`, `fence`, `wall_mounted`.
- **Bridges are dropped** (bridge cells become `floor`). The game already disables them; they were the worst blob artefact.
- Benefits:
  - the model learns size and shape per use (small bedrooms in rows, large dining halls)
  - doorless "rooms" become rarer, since every typed room in the data has a door
  - in game, the type drives furnishing (beds in bedrooms, stove in the kitchen), the open item "furnishing via RoomContentsWorker"
  - typed cells work as seeds: fix a few `kitchen` cells and the model builds a kitchen there. This is a meaningful replacement for
    the wall-fragment seeds.

### 2. A condition input: rock and unbuildable ground

A second input grid, not generated by the model: `0 free`, `1 rock`, `2 unbuildable` (water, marsh, off the map). Its embedding is added
to the token embedding. In game it comes straight from the map (`LayoutPlacer` already builds both masks).

- `rock` in training: the extract's `mountain` mask (unenclosed roofed blobs plus smoothed rock walls), minus cells that hold structure
  or constructed floor.
  - Limit: an unfloored mined-out room looks the same as rock in the snapshots.
  - Check before training: view about 30 mountain windows as ASCII and on a sample sheet.
- `unbuildable` in training: the snapshots barely record natural terrain, so it is synthetic. Random smooth blobs are placed only on
  cells that are empty in the window, plus window edges marked as off the map. The model learns to build around them, not on them.
- Mountain-adjacent buildings (9,260, about a third of all buildings) are added to the set. The v1 config dropped any window with a
  mountain cell.

### 3. Training with fixed regions

MaskGIT training hides random cells. Inpainting in game hides large connected regions, which v1 never trained on.

- Half of the batches use block masks: rectangles and blobs covering 30–90% of the window, with the rest given as context.
- The other half keep random masks, unchanged.

### 4. Milder class weighting

v1 weights rare classes by `weight_power` 0.5, capped at 20. That makes raw samples far too busy (62 rooms per window), and a
logit bias of 0.6 at sampling is needed to undo it.

- v2 uses `weight_power` 0.25 and logs raw sample metrics, aiming to need little or no bias.
- Room types split floor into several classes, so their weights need a look either way.

### 5. Density as an input (optional)

One number per window, the bucketed share of structure cells, given as a learned embedding. It sets density directly instead of
through the seed count. It is cheap to add, and at sampling time the game picks the bucket (vanilla is about 7 rooms per 36x36).

## Steps

1. **Data (CPU).**
   - `extract.py` v2: room labels and types, with the rules in config.
   - `windows.py`: condition grid, mountain windows included, bridge dropped.
   - `report.py`: per-type counts and ASCII samples with the condition grid shown.
   - Check the room-type rules and the mountain mask by eye. *User review point.*
2. **v2a: room types plus milder weights**, flat-ground windows only, no condition input. One change from the `v1_more_mdm`
   baseline, so its effect is measurable. About 1.6 hours on the GPU.
3. **v2b: v2a plus the condition input, mountain windows, block masks and density.** Probably about 2.5 hours (more windows).
4. **Evaluation (Python).** Run all of these on v1_more, v2a and v2b:
   - free generation
   - the mountain test, where the condition channel replaces the shell
   - a water test
   - an inpainting test
   - new room-type metrics: share of typed rooms, size per type against real, and doors per type
5. **Game.**
   - Read categories, the condition input and the density input from `model_meta.json`.
   - Rock and obstacles go in through the condition input. The shell is no longer needed but stays as a toggle for v1 models.
   - The placer gives each room type a floor and later furniture.
   - LayoutCheck parity test against Python again.
